# Рассылка писем из рабочего OWA (Exchange) с ответами в ту же ветку

Инструмент на Python для рассылки типовых писем из рабочего почтового ящика
(локальный Exchange / OWA в закрытом контуре) по списку из Excel, с подстановкой
переменных и возможностью **дослать повторное письмо в ту же ветку переписки**.

Есть два способа использования:

- **Веб-интерфейс** (`web_app.py`) — удобное окно в браузере; можно собрать в
  приложение для macOS (`.app`) или Windows (`.exe`) и запускать двойным кликом.
  См. раздел [«Веб-интерфейс и приложение»](#веб-интерфейс-и-приложение).
- **Командная строка** (`mailer.py`) — для тех, кому удобнее терминал.

Подключение к почте идёт через **EWS (Exchange Web Services)** — штатный
протокол локального Exchange. Облачные Office 365 / Azure-приложения не нужны.

> Запускать нужно **внутри корпоративной сети**, откуда доступен ваш почтовый
> сервер.

---

## Веб-интерфейс и приложение

### Как это выглядит

Окно в браузере с 4 шагами: **Подключение** (email/логин/EWS/пароль) →
**Список контактов** (загрузка Excel) → **Шаблоны** (тексты писем с
предпросмотром) → **Отправка** (рассылка и кнопка «Дослать в ту же ветку»,
журнал отправки в реальном времени).

- Сервер поднимается локально на `127.0.0.1` — данные **не уходят** наружу.
- Пароль хранится только в памяти процесса, никуда не записывается.
- Настройки, шаблоны и история отправки лежат в папке `~/K2-Mailer`
  (на Windows — `C:\Users\<вы>\K2-Mailer`). Благодаря истории «дослать в ветку»
  работает даже после перезапуска приложения.

### Как остановить приложение

Локальный сервер работает внутри процесса приложения. Остановить можно двумя
способами:

- кнопкой **«Завершить работу»** внизу страницы — сервер корректно выключится;
- просто **закрыть окно/вкладку браузера** — приложение само остановится через
  ~15 секунд (страница перестаёт «пинговать» сервер). Во время активной
  рассылки авто-остановка не срабатывает, чтобы не прервать отправку.

Таймаут простоя можно изменить переменной окружения `K2_MAILER_IDLE_TIMEOUT`
(в секундах).

### Корпоративная подпись с фото

В разделе **«Корпоративная подпись с фото»** вставьте готовый HTML-код подписи
(например, из Outlook). Там, где должно быть фото, впишите токен `{photo}` в
адрес картинки:

```html
<table><tr>
  <td><img src="{photo}" width="110" style="border-radius:8px"></td>
  <td style="padding-left:14px;font-family:Arial">
    <b>Фёдор Моргунов</b><br>Менеджер, K2 SDR<br>
    +7 999 000-00-00 &middot; fmorgunov@k2.cloud
  </td>
</tr></table>
```

Загрузите файл фотографии кнопкой «Загрузить фото». При отправке письмо уходит
в формате HTML, а фото **встраивается прямо в письмо** (inline-вложение) — оно
видно у получателя даже в закрытом контуре, без внешних ссылок. Кнопка
«Предпросмотр первого» покажет письмо целиком с подписью и фото.

Подпись и фото хранятся локально (`~/K2-Mailer`), поэтому **у каждого
сотрудника своя**. Если подпись не задана — письма уходят обычным текстом.

### Запуск из исходников (если есть Python)

```bash
pip install -r requirements.txt
python web_app.py        # откроется браузер на http://127.0.0.1:8765
```

### Сборка приложения для сотрудников (двойной клик, без Python)

Сотрудники работают на Mac — соберите `.app` **на любой машине с macOS**
(PyInstaller собирает под ту ОС, на которой запущен):

```bash
chmod +x build_mac.sh
./build_mac.sh
# результат: dist/K2 Mailer.app
```

Раздайте `K2 Mailer.app` (можно заархивировать в zip). Приложение **не подписано**,
поэтому при первом запуске у сотрудника macOS может его заблокировать. Решение —
одно из:

- правый клик по приложению → **Открыть** → ещё раз **Открыть**, либо
- один раз в терминале снять «карантин»:
  ```bash
  xattr -dr com.apple.quarantine "/путь/к/K2 Mailer.app"
  ```

Для Windows аналогично — `build_windows.bat` (запускать на Windows), результат
`dist\K2 Mailer\K2 Mailer.exe` (раздаётся вся папка).

> Сборку достаточно сделать один раз; готовый `.app`/`.exe` копируется на машины
> сотрудников. Для самого приложения Python им не нужен.

## Что умеет

- `send` — первая рассылка по Excel (`Имя`, `Компания`, `Почта`, `Тема письма`),
  с подстановкой `{имя}` и `{компания}` в шаблон.
- `followup` — повторное письмо тем же адресатам, **в ту же ветку** (по теме
  разговора + заголовкам `In-Reply-To`/`References`).
- `--dry-run` — показать, что и кому уйдёт, ничего не отправляя.
- Состояние рассылки сохраняется в `sent_state.json` (прогресс пишется после
  каждого письма — можно прервать и продолжить через `--resume`).

## Установка

```bash
# 1. Зависимости
python -m venv .venv
. .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt

# 2. Настройки подключения
cp config.example.ini config.ini
# откройте config.ini и заполните email, username, ews_url

# 3. (необязательно) пример Excel, чтобы увидеть формат
python make_example_data.py   # создаст contacts.example.xlsx
```

### Где взять `ews_url`

Это адрес OWA, но с хвостом `/EWS/Exchange.asmx`. Если OWA открывается по
`https://mail.company.ru/owa`, то EWS обычно:

```
https://mail.company.ru/EWS/Exchange.asmx
```

Если не знаете точно — оставьте `ews_url` пустым, скрипт попробует
автоопределение. Точный адрес может подсказать ваш IT-отдел.

### Пароль

Пароль **не хранится** в файлах. Скрипт спросит его при запуске. Либо задайте
переменной окружения, чтобы не вводить каждый раз:

```bash
export EWS_PASSWORD='ваш-пароль'      # Windows (cmd): set EWS_PASSWORD=...
```

## Формат Excel

Первая строка — заголовки. Нужны 4 колонки (имена настраиваются в `config.ini`,
раздел `[columns]`):

| Имя   | Компания     | Почта                | Тема письма                  |
|-------|--------------|----------------------|------------------------------|
| Иван  | ООО Ромашка  | ivan@romashka.ru     | Предложение о сотрудничестве |
| Мария | АО Василёк   | m.petrova@vasilek.ru | Сотрудничество с K2 SDR      |

Тема письма у каждого адресата своя — берётся из его строки.

## Шаблон письма

Обычный текстовый файл. Переменные в фигурных скобках, по-русски или
по-английски (равнозначно):

- `{имя}` / `{name}`
- `{компания}` / `{company}`

Примеры — в `templates/letter.example.txt` и `templates/followup.example.txt`.

## Использование

### 1. Проверка без отправки (рекомендуется перед каждой рассылкой)

```bash
python mailer.py send \
  --excel contacts.xlsx \
  --template templates/letter.example.txt \
  --dry-run
```

Покажет тему и текст каждого письма с уже подставленными именами.

### 2. Рассылка

```bash
python mailer.py send \
  --excel contacts.xlsx \
  --template templates/letter.example.txt
```

Результат пишется в `sent_state.json`. Если что-то прервалось — повторный
запуск с `--resume` пропустит уже отправленные адреса:

```bash
python mailer.py send --excel contacts.xlsx --template templates/letter.example.txt --resume
```

### 3. Повторное письмо в ту же ветку

Адресатов и ссылки на исходные письма команда берёт из `sent_state.json`,
поэтому Excel здесь уже не нужен:

```bash
# сначала проверка
python mailer.py followup --template templates/followup.example.txt --dry-run

# отправка
python mailer.py followup --template templates/followup.example.txt
```

Письмо уйдёт тем, кому первая рассылка прошла успешно, с темой `RE: <исходная>`
и привязкой к исходному письму — у адресата оно ляжет в тот же разговор.

Дослать только избранным:

```bash
python mailer.py followup --template templates/followup.example.txt \
  --only ivan@romashka.ru,m.petrova@vasilek.ru
```

Если планируете **третье** письмо в ту же ветку — сохраните id повторных писем:

```bash
python mailer.py followup --template templates/followup.example.txt \
  --followup-state followup_state.json
```

## Полезные опции

| Опция         | Команда         | Назначение                                              |
|---------------|-----------------|---------------------------------------------------------|
| `--dry-run`   | обе             | Показать письма, не отправляя                            |
| `--delay N`   | обе             | Пауза N секунд между письмами (по умолчанию 1)           |
| `--limit N`   | обе             | Отправить не более N писем (для теста на нескольких)     |
| `--resume`    | `send`          | Пропустить уже успешно отправленные адреса               |
| `--only`      | `followup`      | Список адресов через запятую                             |
| `--config`    | обе             | Путь к INI (по умолчанию `config.ini`)                   |
| `--state`     | обе             | Путь к JSON состояния (по умолчанию `sent_state.json`)   |

## Как устроена «ветка» (для понимания)

Outlook у адресата группирует письма в один разговор по **теме** (точнее, по
теме разговора без префикса `RE:`). Дополнительно повторное письмо помечается
стандартными заголовками `In-Reply-To` и `References`, указывающими на исходное
письмо. Эти два механизма вместе дают надёжную склейку в одну переписку, в том
числе в почтовых клиентах, отличных от Outlook.

## Заметки по безопасности

- `config.ini`, `*.xlsx`, `sent_state.json` добавлены в `.gitignore` — личные
  данные и контакты не попадут в репозиторий.
- Пароль нигде не сохраняется; используйте `EWS_PASSWORD` или ввод по запросу.
- `verify_ssl = false` в `config.ini` отключает проверку сертификата — применяйте
  только если в вашей сети самоподписанный сертификат и иначе никак.
- Перед массовой рассылкой прогоните `--dry-run` и проверьте на 1–2 адресах
  через `--limit 1`.
